# Q1 — Create a Deployment

Goal
- Create a `Deployment` named `nginx-deploy` that runs `nginx:1.21`.

Constraints
- Deployment must have `3` replicas.
- Pods must be labeled `app=web`.
- Container must listen on port `80`.
- Add environment variable `ENV=production` in the Pod template.
- Set resource *requests* to `cpu: 100m`, `memory: 128Mi` and *limits* to `cpu: 200m`, `memory: 256Mi`.
- Use `RollingUpdate` strategy with `maxUnavailable` set to `1`.
- Use only manifest files placed under `sessions/quiz-session1/`.

Time limit
- 15 minutes

Success criteria (exact kubectl checks)
- Deployment exists with 3 replicas:
  kubectl get deploy nginx-deploy -o jsonpath='{.spec.replicas}'

- Deployment's Pod template uses the requested image:
  kubectl get deploy nginx-deploy -o jsonpath='{.spec.template.spec.containers[0].image}'

- Pod template contains the `ENV=production` environment variable:
  kubectl get deploy nginx-deploy -o jsonpath='{.spec.template.spec.containers[0].env[?(@.name=="ENV")].value}'

- RollingUpdate `maxUnavailable` is set to `1`:
  kubectl get deploy nginx-deploy -o jsonpath='{.spec.strategy.rollingUpdate.maxUnavailable}'

Notes
Notes
- You may use imperative `kubectl` commands with `--dry-run=client -o yaml` to generate a clean manifest template; save and edit the generated YAML under `sessions/quiz-session1/` before applying.
- When ready, apply your manifest from this folder and paste the output of the verification commands above for grading.
- Reminder: if you apply this manifest to a non-default namespace (for example `quiz1-q1`), include `-n <namespace>` in the verification commands or switch context.
