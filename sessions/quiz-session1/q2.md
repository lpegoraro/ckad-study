# Q2 — ConfigMap + Pod

Goal
- Create a `ConfigMap` named `app-config` and a Pod named `config-demo` that consumes the ConfigMap.

Constraints
- `app-config` must contain a key `APP_MODE` with value `debug`.
- `config-demo` must use the `busybox` image and run `sleep 3600` as its command.
- The Pod must expose the `APP_MODE` value to the container as an environment variable (use `envFrom` or `env` + `valueFrom`).
- Use manifest files placed under `sessions/quiz-session1/`.

Time limit
- 10 minutes

Success criteria (exact kubectl checks)
- ConfigMap key present:
  kubectl get configmap app-config -o jsonpath='{.data.APP_MODE}'

- Pod shows the env var value (pod must be Running):
  kubectl get pod config-demo -o jsonpath='{.status.phase}'
  kubectl exec config-demo -- printenv APP_MODE

Notes
- You may use imperative `kubectl` commands with `--dry-run=client -o yaml` to generate clean manifest templates; save and edit the generated YAML under `sessions/quiz-session1/` before applying.
- When ready, apply your manifests from this folder and paste the outputs of the verification commands above for grading.
- Reminder: if you apply these manifests to a non-default namespace (for example `quiz1-q2`), include `-n <namespace>` in the verification commands or switch context.
